# Base 编码自动识别与格式选择设计

日期：2026-10-15
状态：设计已批准；实现完成（v2.9.0，本地未发布）

## Goal

扩展「密文自解」现有 Base64 双向转换，使帖子正文与面板手动解码都能识别已约定的 Base 格式；明文加码时可选择格式。示例帖子已在独立登录态浏览器中只读确认其编码标签为 Base58；示例串看起来像 key，不会复制到规格、源码或测试夹具。

## 当前基线

- 帖子正文扫描最终调用 `resolveText` / `decodeOnce`，只按 Base64 与 Base64URL 解释候选。
- 手动面板调用 `decodeManualInput`，提供整串优先、失败后分段尝试以及最多三轮解码。
- 加码器使用 UTF-8 字节输入和手写 Base64，现有参数包括轮数、Base64URL 字母表、折行与空白处理。
- 本设计保留现有的帖子扫描范围、输出渲染、复制行为、字符过滤与逐层上限；不引入外部运行时依赖。

## 术语

- **Base 编码**：可逆的数据表示方式，不提供加密或保密性。
- **格式自动识别**：对一个候选串尝试已支持的解码格式，并依格式校验与文本判据决定结果。
- **歧义候选**：多个格式产生不同的可读文本结果；若多个格式产生相同文本则合并为一个结果。Base64 与 Base64URL 仅共享字母表时按 Base64 标记；出现 `-` 或 `_` 时按 Base64URL 标记。
- **手动指定格式**：由面板选择解码/编码格式，覆盖自动识别或默认格式。

## 方案比较

1. 在 Base64 函数旁单独增加 Base58 分支：局部改动快，但多个算法会分散在正文扫描和手动转换路径中，后续扩展易出现行为不一致。
2. **共享 codec 注册表（推荐）**：以格式标识统一组织规范化、字节解码、字节编码和输出名称；正文自动扫描与手动面板复用相同实现，并在调用层分别执行自动/强制模式。
3. 引入第三方编码库：减少部分算法代码，但给单文件用户脚本增加依赖、体积及供应链维护面，当前需求不值得承担。

## 选定设计

### 支持格式

首版支持：

- Base16（Hex，大小写均可）；
- RFC 4648 Base32；
- Bitcoin 字母表的原始 Base58；
- 标准 Base64；
- Base64URL。

暂不支持 Base58Check、Ascii85/Z85、basE91 及其他非上述变体。Base64URL 继续复用现有 URL-safe 行为与持久化设置；其他格式不显示或忽略该选项。

### 解码路径

1. 帖子正文扫描：对现有候选串尝试所有支持格式；将解码后文本相同的候选合并，只有恰好一个不同文本结果通过语法校验、严格 UTF-8 解码、现有最小长度与可打印性门槛，才自动替换为解码文本。零个结果或多个不同结果均保持原文。Base64 与 Base64URL 使用共同字母表且结果相同时归并为 Base64；输入含 `-` 或 `_` 时按 Base64URL 识别。
2. 手动面板：解码格式选择默认为「自动识别」，对产生不同可读文本结果的歧义输入显示各候选，用户可从同一输入直接选择格式重算；相同文本结果合并。手动强制格式时只执行所选格式，不再以其他格式替代。
3. 多层输入：每轮独立重新识别格式，可处理不同 Base 格式层叠；遵守当前解码轮数上限、短串停止、URL/密钥等既有下钻停止条件。输出标签注明每轮识别的格式；歧义或失败时停止在最后一个已确认的文本结果。
4. Base58 还原必须保留前导零字节；Base16 要求完整字节对；Base32 按 RFC 4648 字母表及 padding 规则校验；标准 Base64 与 Base64URL 保持现有空白、padding 归一化能力。
5. 保留现有手动模式的首轮宽松 UTF-8 回退与 `lossy` 标记；正文自动替换和后续下钻仍只接受严格 UTF-8。自动候选判定不以「能得到任意字节」为成功。

### 加码路径与 UI

- 面板增加「Base 格式」选择器，默认 Base64；选项为 Base16、Base32、Base58、Base64、Base64URL。解码方向额外有「自动识别」。
- 加码方向的现有轮数、折行与空白处理继续工作；选择的格式应用于每一层。仅 Base64/Base64URL 使用其对应字母表与 padding 规则，其他格式按其标准输出。
- 解码结果标题标明实际格式；多轮时逐层显示格式与轮次。复制按钮仍复制最终显示文本，现有主题样式与输入框行为保持不变。
- `cleanInput`、整串优先及失败后分段尝试仍保留；分段候选字符集扩展以覆盖 Base16/Base32/Base58，并用 codec 校验避免仅凭字符集认定格式。

## 错误与歧义处理

- 自动扫描：无效、不可读、太短或歧义时不改帖子 DOM。
- 手动自动模式：无有效候选显示现有解码失败状态；多候选显示可选择的格式与文本预览，不静默挑选。
- 手动强制模式：格式不匹配时显示该格式解码失败，不回退到另一算法。
- 加码：空输入保持现有空输入错误；格式函数异常显示失败，不清空或覆盖原输入。

## 回归测试与验收

- 固定向量：Base16/Base32/Base64 可读文本；Base58 可读文本、前导零字节与含非法字母的输入；Base64URL 无 padding。
- 对每个格式运行文本 → 编码 → 指定格式解码往返断言；覆盖中文、emoji 与换行。
- 自动探测断言：唯一格式成功、无效载荷不替换、同一串多格式歧义时保留原文，并在手动模式可显式选择。
- 嵌套断言：同格式及混合格式多层输入逐层识别，达到既有轮数上限后停止。
- 帖子扫描回归：Base64 原有识别不退化；Base58 唯一可读候选可识别；普通正文与歧义字母数字串不被误改。
- UI 回归：格式选择、Base64URL 选项显示/隐藏、格式标签、复制最终解码结果、参数保存与重置。
- 验收命令：`node scripts/run-selfcheck.cjs` 全部断言通过；`node --check linuxdo-toolbox.user.js`、`node --check scripts/run-selfcheck.cjs` 与 `git diff --check` 通过。

## Boundaries

- 不改变 Cloudflare 过盾逻辑、其他六项功能、站点请求或帖子交互。
- 不把用户提供的帖子 key-like 示例值存入源码、README、测试、提交信息或报告；使用人工构造的非敏感向量。
- 本设计阶段不修改源码、不发布、不提交 Git。
